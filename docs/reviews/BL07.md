**Rama:** `fase/bl07` desde `main@1db6944`. Salida real: `BL07_SALIDA.txt`.

## Brief corto

- **Problema:** un Asset puede quedar `UPLOADING`/`VALIDATING` si el proceso
  muere o la base falla a mitad del pipeline (§33). Hoy no hay forma operativa
  de verlos.
- **Alcance (primera etapa del backlog):** solo un reporte. Criterio: un Asset
  `VALIDATING`/`UPLOADING` con `updated_at` > TTL aparece; uno reciente no.
- **Fuera de alcance:** cualquier acción sobre esos Assets (reintentar,
  cerrar, rechazar), códigos contractuales nuevos, BL-08 (blobs huérfanos),
  ruta HTTP o UI.

## Decisiones

1. **CLI de operación, no endpoint.** `pnpm --filter @trust/platform-api
   assets:stale-report -- --older-than-minutes N [--limit M]`, igual que
   `user:create`: corre con `DATABASE_URL` en el servidor. No agrega superficie
   HTTP ni roles nuevos.
2. **Read-only garantizado por PostgreSQL:** la primera sentencia es `SET
   TRANSACTION ISOLATION LEVEL REPEATABLE READ, READ ONLY`; cualquier escritura
   posterior falla en la base y conteo y lista salen del mismo snapshot. No
   hay audit (nada cambia) ni acceso a storage.
3. **Reloj de PostgreSQL:** el corte es `now() - umbral`, el mismo reloj que
   escribe `updated_at` (`trust_set_updated_at`). No depende del reloj del host.
4. **Umbral:** `--older-than-minutes` (1 a 525 600), o
   `ASSET_STALE_AFTER_MINUTES` (agregada a `.env.example`), o 60. El argumento
   gana a la variable. Comparación estricta: exactamente en el borde no entra.
5. **Salida JSON** con `generatedAt`, `olderThanMs`, `total`, `byStatus`,
   `truncated` e `items` del más viejo al más nuevo (`updated_at` asc, id).
   `--limit` (1–10 000, default 500) corta la lista pero no el conteo. Código 0
   aunque haya vencidos: es un reporte, no una alarma.
6. **Mínimos datos:** `assetId`, `status`, `surfaceType`, `createdBy`,
   `createdAt`, `updatedAt`, `staleForMs`. Sin nombre de archivo (puede llevar
   datos del cliente) ni metadatos de medios.

### B. Revisión adversaria

- **Bordes del umbral:** 59 min con TTL 60 no entra; 0, negativos,
  decimales, texto, vacío y valores enormes se rechazan (también desde la
  variable de entorno); opciones desconocidas (`--fix`, `--reject`) y
  posicionales también.
- **Reloj:** el host puede tener otro reloj que la base; por eso el corte y
  `staleForMs` salen de `now()` de PostgreSQL (test: `generatedAt − updatedAt
  = staleForMs`).
- **Volumen:** `--limit` acota la salida; `total`/`byStatus` siguen siendo el
  conteo completo y `truncated` lo avisa (mutación).
- **Concurrencia:** conteo y lista comparten snapshot (REPEATABLE READ), así
  que `total` y `truncated` son coherentes con `items`. Un Asset que termina
  mientras corre puede figurar como vencido en ese snapshot; el reporte no
  actúa sobre lo que lista.
- **Permisos/datos:** corre con el rol `trust_app` del servidor; la salida no
  lleva nombre de archivo (test y mutación "fila cruda").
- **Errores de infraestructura:** si la base no responde, el CLI falla con el
  error y código distinto de 0; no deja nada a medias porque no escribe.
- **Decidido no hacer:** sin índice nuevo por `(status, updated_at)` (sería
  una migración; la tabla es chica y el reporte es manual) y sin
  `count`/lista en una sola sentencia (dos SELECT en el mismo snapshot).
