## Decisiones tomadas

1. `DECISIONES.md` es alto (no medio): puede autorizar cosas. Consecuencia: #72 sale alto.
2. `BACKLOG.md` es medio (no bajo): marcar un ítem `aceptada` habilita laterales (P-05).
3. Contenido se mira solo en código para procesos/DDL/secrets-ctx (un `.md` que *menciona* `spawn(` sigue bajo); tokens reales se miran en todo archivo.
4. El check corre para todo PR (también hacia ramas de fase) pero solo es vinculante para PRs hacia `main`. Un PR hacia otra base publica `riesgo (otra base)` y queda fuera de la dominancia por HEAD de `riesgo`, así no pinta de rojo a un PR hacia `main` con el mismo HEAD (AUDIT: CAMBIOS @ `94bad43`, P2). El nombre se recalcula desde cada foto refrescada antes de publicar un `caducado` (AUDIT: CAMBIOS @ `9a7170b`, P2).

## Límites declarados

- Es un **mínimo**: CI no declara seguro ningún diff; el auditor decide siempre (#53).
- Una asignación a un nombre de credencial con valor entre comillas de 16+ caracteres (también con espacios) es alto aunque sea un password de test o prosa: en el repo actual aparecen 9 líneas así (tests de DB/auth, una SALIDA); se acepta como falso positivo fail-closed (AUDIT: CAMBIOS @ `e08a47b`, P2).
- Heurísticas de contenido por regex: pueden dar alto de más (aceptado: fail-closed); no detectan un cambio peligroso escrito en una ruta medio sin palabras clave (por eso medio sigue con auditoría completa).
- Entra en vigor al estar en `main`; en este PR no corre (igual que `paralelo.yml`). La protección de rama (required checks) sigue pendiente de Fer.
- Lint: `pnpm lint` cubre `{packages,apps}/*/src`; los `.mjs` de `scripts/collab` quedan fuera igual que `progreso.lib.mjs` (no se cambia el alcance del lint en este PR).
