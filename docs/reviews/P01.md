**Comandos de `handoff.sh`:**

- **`leer`:** hace fetch, muestra el HANDOFF de `origin/main` e imprime
  `HANDOFF_BASE_SHA`.
- **`validar`:** comprueba que el archivo tenga:
  - como máximo 60 líneas;
  - exactamente una línea `**Pelota en:** Claude|ChatGPT`;
  - ningún marcador de conflicto.
- **`escribir`:** hace compare-and-swap contra `HANDOFF_BASE_SHA`.
  - Si `main` avanzó, aborta (exit 3) y muestra el diff de HANDOFF, HISTORIAL
    y DECISIONES.
  - Si no, commitea sobre `origin/main` exacto (worktree detached) y hace un
    push **solo fast-forward**, sin `--force`.

**Ronda de hoy (2026-10-12):** merge de `main` (F3(a) API y UI) sin
conflictos. El script y su prueba no cambian desde `a4121dc`, que tenía CI 7/7
en la run 38158190099.

## Autorrevisión

### A. Contra P-01 ajustado (#53)

| Requisito | Dónde | Prueba |
|---|---|---|
| Leer antes de escribir, con base explícita | `leer` + `HANDOFF_BASE_SHA` obligatoria | caso 6 "sin HANDOFF_BASE_SHA → rechazo" |
| Si `main` avanzó: abortar y mostrar lo no visto, sin pisar | `escribir`, rama `ACTUAL != BASE` | casos 3.1–3.4 |
| Commit sobre la base exacta y push solo fast-forward; nunca `--force` (ajuste del auditor) | worktree detached + `git push <sha>:refs/heads/main` | caso 4.3 (historia lineal), caso 5 (carrera fetch→push rechazada por git), caso final (ningún push con force) |
| Formato del HANDOFF en CI | `validar` en `verify-build` | caso 6; además corre sobre el HANDOFF real de `main` |
| Regla P-05 (no tocar el HANDOFF con la pelota ajena) | `AGENTS.md` | Regla de proceso; el script no puede forzarla. Ver límites |

### B. Revisión adversaria

- **Carrera entre fetch y push:** git rechaza el push non-fast-forward, sale
  con exit 3 y no se reescribe nada. Hay un test.
- **CAS conservador:** compara el SHA completo de `main`, no solo el del
  HANDOFF. Cualquier commit en `main` (por ejemplo, el merge de un PR) obliga
  a releer. Es deliberado: más barato que razonar qué cambios "no importan".
- **Entorno:** el test aísla la config global (`GIT_CONFIG_GLOBAL=/dev/null`)
  y usa un remoto bare temporal.
- **El HANDOFF actual, escrito con otro formato por el auditor, pasa
  `validar`:** comprobado localmente.

### C. CI

Se cita en el PR el link de la corrida y el SHA exacto del HEAD.

## Límites declarados

- El script no impide que otra herramienta escriba `main` por otro camino.
  Para eso hace falta la **protección de rama `main`** en GitHub, con CI
  requerido: queda **pendiente de Fer**, como pidió el auditor en #53.
- Las sesiones paralelas de Claude, por ejemplo el chequeo horario, también
  tienen que usar el script. La regla queda en `AGENTS.md`.
